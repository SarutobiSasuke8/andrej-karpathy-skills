# 安全默认值

安全代码不是一个独立的关注点——它是一个质量标准。这些是默认值，而不是例外情况。

**权衡：** 某些默认值会增加少量摩擦。这种摩擦正是其意义所在。

## 1. 在边界处验证

**不信任任何跨越信任边界的内容。**

- 在数据进入系统的入口处验证所有输入：HTTP 请求、文件上传、CLI 参数、环境变量、来自外部系统的数据库读取。
- 尽早拒绝——不要将未经验证的数据传递到调用栈深处。
- 不要以不同方式对同一输入验证两次。选择一个地方。
- 你拥有的代码之间的内部函数调用不需要防御性验证——那是噪音，不是安全。

## 2. 代码中不存储密钥

**凭证永远不属于源文件。**

- 不要在签入版本控制的代码或配置文件中放置 API 密钥、密码、令牌或私钥。
- 使用环境变量或密钥管理器。通过名称引用它们，永远不要内联值。
- 如果你在 diff 中看到密钥，立即将其视为已泄露——轮换，而不仅仅是删除。
- `.env` 文件仅用于本地开发。它们必须在 `.gitignore` 中。

## 3. 默认最小权限

**只申请你需要的访问权限。尽可能缩小范围。**

- 数据库凭证应只拥有应用程序实际使用的权限（只读服务用 SELECT，应用程序账号不需要 DROP 或 CREATE）。
- API 令牌应限定在所需的最小端点范围内。
- 文件操作应使用能正常工作的最低权限模式。
- 有疑问时，从少开始扩展，而不是从多开始限制。

## 4. 输出编码与目标匹配

**为数据将要去的地方编码，而不是它来自哪里。**

- 数据进入 HTML → HTML 编码它。
- 数据进入 SQL 查询 → 使用参数化查询，永远不要字符串拼接。
- 数据进入 shell 命令 → 使用参数数组，永远不要字符串插值。
- 数据进入 URL → URL 编码它。

同一个字符串在不同目标中需要不同处理。不要在输入时提前编码——在使用时编码。
